# Tender Monitoring Bot (Кыргызстан)

Мониторинг тендеров с 5 площадок, фильтрация по ключевым словам,
уведомления на Gmail, отслеживание отмен и победителей. Работает
полностью на GitHub Actions без сервера.

## Структура проекта

```
tender-bot/
├── bot.py                          # основной скрипт
├── requirements.txt
├── tenders_db.json                 # база тендеров (создаётся автоматически)
├── sent_tenders.json               # плоский список уже отправленных ID (для совместимости)
└── .github/
    └── workflows/
        └── tender_bot.yml          # расписание + автокоммит базы
```

## Настройка

### 1. Пароль приложения Gmail

Обычный пароль от Gmail для SMTP не подойдёт. Нужно:
1. Включить двухфакторную аутентификацию в аккаунте Google.
2. Создать "Пароль приложения" (App Password): https://myaccount.google.com/apppasswords
3. Использовать этот 16-значный пароль как `GMAIL_APP_PASSWORD`.

### 2. Secrets репозитория (Settings → Secrets and variables → Actions → Secrets)

| Имя | Пример значения | Описание |
|---|---|---|
| `GMAIL_USER` | `mybot@gmail.com` | Аккаунт, с которого шлются письма |
| `GMAIL_APP_PASSWORD` | `abcd efgh ijkl mnop` | Пароль приложения Gmail |
| `TO_EMAILS` | `mail1@gmail.com, mail2@mail.ru` | Получатели через запятую |

### 3. Variables репозитория (там же, вкладка Variables)

| Имя | Пример значения | Описание |
|---|---|---|
| `KEYWORDS` | `ремонт дорог, строительство, IT оборудование` | Ключевые слова через запятую |
| `MY_COMPANY_NAMES` | `ООО Ромашка, ИП Иванов` | Ваши названия компаний для проверки победы |

Variables используются вместо Secrets для KEYWORDS/MY_COMPANY_NAMES,
потому что это не чувствительные данные и их удобнее редактировать —
но при желании можно перенести их и в Secrets, поменяв `vars.` на
`secrets.` в `tender_bot.yml`.

### 4. Права на запись для workflow

Settings → Actions → General → Workflow permissions →
**Read and write permissions** (иначе `git push` из workflow не сработает).

### 5. Первый запуск

Запустите workflow вручную (Actions → Tender Monitoring Bot → Run workflow),
чтобы убедиться, что письма приходят и `tenders_db.json` коммитится.

## Важно про парсеры (`parse_*` функции в bot.py)

Каждая площадка (`zakupki.gov.kg`, `tenders.kg`, `aris.kg`,
`goszakupki.okmot.kg`, `procurement.kg`) имеет свою вёрстку, и часть из
них (например, `tenders.kg`) требует авторизации либо рендерит список
через JavaScript. В коде каждая функция `parse_<site>` содержит
рабочий каркас запроса + разбора HTML, но CSS-селекторы отмечены как
`TODO` — перед продакшн-использованием откройте страницу в браузере,
посмотрите DevTools → Elements/Network и подставьте реальные селекторы
(или, если данные приходят через JSON-API, замените парсинг HTML на
прямой запрос к этому API — это надёжнее).

## Известные проблемы с площадками (обновлено после разбора реальной разметки)

- **zakupki.gov.kg — исправлено (лейблы оказались на русском)**.
  Диагностика показала, что реальные "прилипшие" лейблы в таблице —
  `"Наименование организации"` (заказчик) и `"Наименование закупки"`
  (название тендера) на русском языке, а не английские `"purchase
  Name"`/`"Name of company"`, как я предположил раньше по неполной
  markdown-выжимке страницы. Сопоставление обновлено на реальные
  русские лейблы. Поля `deadline` (`"срок подачи предложений"`) и
  `published` (`"дата публикации"`) — по аналогии, но их точный текст
  пока не подтверждён напрямую (не было видно в диагностическом логе);
  если после следующего запуска в письмах эти поля будут пустыми —
  можно временно вернуть подробный диагностический вывод всех полей
  строки, а не только title, чтобы уточнить.

- **aris.kg — ИСПРАВЛЕНО**. Раздел тендеров лежит на `/tenders` (а не
  на главной странице, как было раньше), верстка — простая HTML-таблица
  без JS. Парсер обновлён, читает первые 3 страницы (`/tenders`,
  `/tenders/2`, `/tenders/3`).

- **goszakupki.okmot.kg — ИСПРАВЛЕНО (найден JSON API)**. Сайт — React
  SPA, но список тендеров приходит через открытый JSON-эндпоинт:
  `GET https://goszakupki.okmot.kg/api/public_tender/published?first=0&rows=50`
  Парсер обновлён и делает прямой запрос к этому API — надёжнее и быстрее
  HTML-парсинга. Два нюанса, которые стоит знать:
  1. Статусы в API — латинские enum-значения (`VERIFIED_PUBLISHED` и
     т.п.). Мы наблюдали только "опубликован"; маппинг для "отменен"/
     "завершен" в `_normalize_goszakupki_status()` основан на разумных
     предположениях по названию — если бот когда-то неправильно
     определит статус, нужно будет посмотреть реальное значение поля
     `status` у такого тендера и уточнить маппинг.
  2. Ссылка на страницу тендера подтверждена вручную:
     `https://goszakupki.okmot.kg/public/order/view/{id}?tab=tender`
     — уже вписана в код. На самой странице тендера видели статус
     "Не состоялся" — значит, у площадки есть и другие статусы, кроме
     "опубликован", просто список `/published` их не отдаёт.
  3. **Победитель/участники — реализовано** через ещё один найденный
     вами API:
     `GET /api/public_submission/getSubmissionsbyTenderId?tenderId=<id>`
     На момент проверки вернул пустой список (у тестового тендера пока
     нет заявок), поэтому точные названия полей внутри одной заявки
     (название компании, отметка победителя) — предположение по
     наиболее вероятным вариантам (`companyName`, `isWinner` и т.п.),
     не подтверждённое на реальных данных. Если после недели работы
     бота победитель для явно завершённого тендера всё равно не
     определяется — откройте такой тендер, найдите в Network тот же
     запрос `getSubmissionsbyTenderId` и пришлите Response — поля будут
     скорректированы под реальную структуру.
  4. **Важное ограничение по отслеживанию отмены/завершения**: список
     `/published`, судя по всему, отдаёт только активные объявления —
     то есть тендер, скорее всего, просто **исчезает** из списка при
     отмене/завершении, а не появляется в нём с новым статусом. Текущая
     логика бота (`run()`) определяет смену статуса, когда тот же ID
     появляется повторно с другим статусом — а не когда ID пропадает из
     выдачи. Это значит, что для `goszakupki.okmot.kg` уведомления об
     отмене тендера в текущей реализации могут не приходить. Если это
     критично — нужно доработать логику отдельно (например, при каждом
     запуске дополнительно опрашивать `/api/public_tender/get/<id>` для
     всех активных тендеров из базы, а не только тех, что попали в
     свежую выдачу `/published`).

- **tenders.kg, procurement.kg — 403 Forbidden, не решено заголовками**.
  Проблема, скорее всего, в блокировке IP-адресов дата-центров, на
  которых работает GitHub Actions (см. ниже). Без переноса запуска на
  обычный сервер/компьютер эти две площадки, вероятно, не заработают
  в текущей схеме.

- **tenders.kg и procurement.kg — ПОЛНОСТЬЮ РАБОТАЮТ (запуск с домашнего IP)**.
  Итоговая картина после отладки: 403 в GitHub Actions действительно
  был блокировкой по IP облака — с домашнего IP оба сайта отвечают без
  ошибок. `tenders.kg` дополнительно требует логина (реализовано через
  `requests.Session()` с вашим `TENDERS_KG_USERNAME`/`TENDERS_KG_PASSWORD`
  из `.env`, без reCAPTCHA). После решения этих двух проблем оставалась
  третья, неожиданная: оба сайта возвращали 0 записей без единой ошибки
  — причина оказалась в заголовке `Accept-Encoding: gzip, deflate, br`:
  библиотека `requests` не может автоматически распаковать Brotli (`br`)
  без отдельного pip-пакета `brotli`, которого не было установлено, из-за
  чего ответ сервера приходил как нечитаемый набор байт вместо HTML.
  Исправлено — из заголовка убран `br`, теперь `tenders.kg` находит
  ~15 записей, `procurement.kg` — ~24 записи, названия и ссылки корректны.
  Работают через локальный запуск (`run_local.ps1` + `ONLY_SOURCES`),
  остальные три площадки — на GitHub Actions, как и раньше.

### Про блокировку IP облачных дата-центров (актуально только для GitHub Actions)

Если после всех правок `tenders.kg` и `procurement.kg` продолжают
отдавать 403 — это означает, что сайт блокирует не по заголовкам
запроса, а по диапазону IP-адресов (Microsoft Azure, на котором крутится
GitHub Actions, попадает в такие блок-листы у многих гос./коммерческих
сайтов КР). В этом случае варианты:
1. Запускать `bot.py` по cron на своём компьютере/VPS с обычным IP —
   логика бота от этого не меняется, просто вместо workflow используется
   обычный cron/Task Scheduler и обычный `git push` из-под учётки с
   Personal Access Token.
2. Использовать резидентный (не датацентровый) прокси-сервис — платно,
   добавляет сложности.

## Локальный запуск для tenders.kg / procurement.kg

Эти две площадки блокируют запросы с IP-адресов GitHub Actions (403
Forbidden) — обходится только запуском с обычного "домашнего"/рабочего
IP. Схема: три рабочие площадки (`zakupki.gov.kg`, `aris.kg`,
`goszakupki.okmot.kg`) остаются на GitHub Actions без изменений, а эти
две — на вашем компьютере через Windows Task Scheduler. Оба процесса
пишут в один и тот же `tenders_db.json` в репозитории, поэтому
дублирования не будет.

### Шаг 1: Установите Git и Python на компьютер (если ещё не установлены)

- Git: https://git-scm.com/download/win
- Python 3.12+: https://www.python.org/downloads/ (при установке
  отметьте галочку "Add python.exe to PATH")

### Шаг 2: Скачайте репозиторий на компьютер

```powershell
cd C:\Users\ВашеИмя\Documents
git clone https://github.com/mrboikonov/Tenderbot.git
cd Tenderbot
pip install -r requirements.txt
```
При клонировании Git попросит логин — используйте Personal Access
Token вместо пароля (GitHub → Settings → Developer settings →
Personal access tokens → Generate new token, права `repo`).
Один раз выполните `git config --global credential.helper store`,
чтобы токен запомнился и не спрашивался каждый раз.

### Шаг 3: Создайте локальный файл .env с секретами

Скопируйте `.env.example` в `.env` (обычное копирование файла,
переименовав) и заполните реальными значениями — тем же
`GMAIL_USER`/`GMAIL_APP_PASSWORD`/`TO_EMAILS`/`KEYWORDS`/
`MY_COMPANY_NAMES`, что и в GitHub Secrets. Файл `.env` уже в
`.gitignore`, в репозиторий он не попадёт — секреты остаются только
на вашем компьютере.

**Не меняйте** строку `ONLY_SOURCES=tenders_kg,procurement_kg` в
`.env` — именно она ограничивает локальный запуск только этими двумя
площадками (иначе будет дублирование работы с облачным запуском).

### Шаг 4: Проверьте вручную

```powershell
cd C:\Users\ВашеИмя\Documents\Tenderbot
powershell -ExecutionPolicy Bypass -File run_local.ps1
```
Если появится ошибка про `ExecutionPolicy` — она означает, что Windows
по умолчанию блокирует запуск скриптов; флаг `-ExecutionPolicy Bypass`
выше это обходит разово, без изменения системных настроек.

Проверьте файл `run_local.log`, который появится рядом — там будет лог
этого запуска (то же самое, что вы видели в GitHub Actions).

### Шаг 5: Настройте Windows Task Scheduler (планировщик заданий)

1. Откройте **Планировщик заданий** (Win+R → `taskschd.msc`).
2. **Создать задачу** (не "Создать простую задачу" — там меньше настроек).
3. Вкладка **Общие**: имя "Tender Bot Local", отметьте **"Выполнять
   вне зависимости от того, выполнен ли вход пользователя"** — тогда
   задача сработает, даже если вы просто включили компьютер и не
   вошли в аккаунт сразу.
4. Вкладка **Триггеры → Создать**: "Ежедневно", время — например
   12:00 (когда вы обычно за компьютером). Внизу отметьте галочку
   **"Выполнить задачу как можно быстрее после пропущенного запуска"**
   — это то самое "догоняющее" поведение: если компьютер был выключен
   в 12:00, задача запустится сразу после включения.
5. Вкладка **Действия → Создать**: Действие "Запуск программы",
   Программа: `powershell.exe`, Аргументы:
   ```
   -ExecutionPolicy Bypass -File "C:\Users\ВашеИмя\Documents\Tenderbot\run_local.ps1"
   ```
6. Сохраните, при запросе введите пароль от вашей учётной записи Windows.

Проверить, что всё сработало — можно вручную кликнуть правой кнопкой
на созданную задачу → **Выполнить**, затем посмотреть `run_local.log`.

## Фильтр по сроку подачи заявки и просмотр всех тендеров

Письмо "Новые тендеры" теперь показывает только **актуальные** тендеры —
те, где срок подачи заявки ещё не прошёл (или неизвестен — в этом
случае бот на всякий случай считает тендер актуальным, чтобы не
пропустить настоящий действующий тендер). Уже просроченные всё равно
сохраняются в базу, просто не попадают в письмо.

**Важная оговорка**: срок подачи надёжно известен только для `aris.kg`
и `goszakupki.okmot.kg` (реальные даты с площадки). Для `zakupki.gov.kg`
— по предположению (лейбл `"срок подачи предложений"` не проверен на
живых данных). Для `tenders.kg` и `procurement.kg` срок пока не
извлекается вообще — такие тендеры всегда считаются актуальными
(увидите их в письме независимо от реального срока, нужно проверять
вручную на сайте).

### Просмотр всех тендеров (актуальные / просроченные)

```powershell
python generate_report.py
```

Читает `tenders_db.json`, создаёт файл `tenders_report.html` и
открывает его в браузере — там два раздела: "Актуальные" и
"Просроченные / пройденные", с сортировкой по сроку подачи и ссылками
на каждый тендер. Можно запускать в любой момент, независимо от
`bot.py` — данные берутся из уже накопленной базы.

## Единая кнопка "проверить всё сразу" (check_now)

Хотите одним кликом: обновить облачные результаты, проверить локальные
площадки и увидеть всё в одном месте? Используйте `check_now.bat`.

### Что он делает
1. (Опционально) Запускает облачный workflow на GitHub через API и
   дожидается его завершения — если в `.env` задан `GITHUB_PAT`
   (см. `.env.example`, нужен Personal Access Token с правами `repo` и
   `workflow`). Без токена просто использует последний результат,
   который облако уже насчитало по расписанию.
2. Подтягивает результаты, запускает локальную часть (`tenders.kg`,
   `procurement.kg`), коммитит.
3. Открывает `generate_report.py` — единую страницу со всеми 5
   площадками сразу (актуальные / просроченные), в браузере.

### Как создать ярлык на Рабочем столе
1. Найдите файл `check_now.bat` в папке репозитория (`Проводник`).
2. Нажмите на него правой кнопкой → **Отправить → Рабочий стол
   (создать ярлык)**.
3. На Рабочем столе появится ярлык — переименуйте его, например,
   в "Проверить тендеры". По желанию смените иконку через Свойства
   ярлыка → Изменить значок.

Теперь достаточно дважды кликнуть по этому ярлыку — откроется чёрное
окно с процессом, а в конце сам откроется браузер с готовым отчётом.

## Логика статусов

- Новый тендер → сохраняется со статусом `Активен`, шлётся письмо "Новые тендеры".
- Если статус меняется `Активен → Отменен` → отдельное письмо-предупреждение.
- Если статус становится `Завершен` → бот пытается спарсить победителя/участников
  со страницы тендера и включает это в сводное письмо "Итоги тендеров".
- Если победитель совпадает с одним из `MY_COMPANY_NAMES` → отдельное
  письмо "🎉 Поздравляем!".
